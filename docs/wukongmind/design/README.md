# WukongMind design files (exported for implementers)

Copies of the owner-confirmed design artifacts, so agents that can't open claude.ai artifacts can implement them. The artifacts remain the source of truth: this folder is a read-only export, never edited by hand, and is re-exported after every artifact change, with a PNG of every new or changed artboard (see [../README.md](../README.md) "Where design output lives").

- `design-system/`: the WukongMind design system (https://claude.ai/artifact/5fGhnS4fmcmWYZbPoKTTZ2), exported 2026-11-13. `README.md` (foundations, colour meanings, the ring, shape, type, motion, the DCTheme migration table), `tokens.json` (colour tokens light/dark, type styles, spacing, radius, shadow, border), `components/<Name>/README.md` + `preview.html` (reference drawings in HTML/CSS using the token CSS variables; implement in SwiftUI), `assets/Logo/` and `assets/Mascot/` (SVGs, the 1024 app icon PNG, usage READMEs).
- `unified-canvas/`: the boards of the unified interface design (https://claude.ai/artifact/Daefr4AsZcSm2EWbTLU9uK), exported 2026-11-13 (re-exported the same day with the M3 and One loop boards, canvas version 57; WUKO-77's boards added 2026-11-14, canvas version 63, plus Fable second-review updates synced back in D1; the M4 boards added 2026-11-15, canvas version 65). Each `*.dc.html` is one board's markup and CSS (light theme variables in `.lt`, dark in `.dk`; `*Dark.dc.html` boards just render the light board with the dark theme). They depend on the design tool's runtime, so they won't render standalone in a browser: read them as layout and style specs. `canvas.json` lists the boards and their order. Image references point to the files in `design-system/assets/`. The written spec is `docs/wukongmind/design-unified.md`. `png/<Board>.png` holds 2x PNGs of the boards added or changed since the first export (light and dark), rendered locally with headless Chrome from these files (theme filled in, image paths pointed at `design-system/assets/`); the boards' own markup stays the spec.

Key boards: `PhonePanelForum`, `PhonePanelPage`, `PanelStates`, `KeyboardUp`, `SuggestionRow`, `PhoneThisPage` (assistant panel); `PhoneHome`, `IPadHome` (start page); `PhoneSettings`, `PhoneModels`, `PhoneAgentSettings`, `PhoneSites`, `IPadSettings` (settings); `PhoneOnb1-3`, `IPadOnb` (onboarding); `Motion`; `IA` (screen map), `Migration`, `Glossary`. `PhoneResearch` shows the One loop stage, not One panel. M3 (spec `design-m3.md`): `PhoneConfirm` (the confirmation card: login on another site, cookies, after Don't allow), `PhoneScreenshot` (screenshot thumbnail in the tool row, full-size sheet, warning before and after). One loop (spec `design-one-loop.md`): `PhoneSavedAnswer` (read-only saved answer from History or Home's Recent), `PhoneVoice` (voice turns in the conversation). Each has a `*Dark` board. WUKO-77 (spec `design-browser-bar-tabs-models.md`, proposed): `PhoneBar` (Safari-like bar keyframes, Agent running, top position, Home, motion), `IPadBar`, `PhoneTabs` (tab overview, one conversation per tab, closing a tab), `IPadTabs`, `PhoneProviderModels` (the provider page's Models list, ⋯ menu, states, no tool calling); each has a `*Dark` board. M4 (spec `design-m4.md`): `M4ImportPhone` (the import review sheet: new script top and scrolled, update form, can't import), `M4ImportPad` (the same sheet as an iPad form sheet: new and update), `M4ScriptDetail` (Update available, Can use, AI use and Clear AI cache, Check now, Let the Agent fix it), `M4ThisPage` (menu commands, fix button, model unreachable line; the Fixed card with Undo; the Uses AI card), `M4Settings` (Settings › Scripts with Import from link…, Check for updates and AI in scripts; Models with the Scripts row and page). Each has a `*Dark` board. Their PNGs were rendered the same way.
