# M0: Forumind Module Map and Change List for WukongMind

> **Historical document.** This M0 survey was written against the initial [requirements.md](requirements.md) before Cleanup 3 renamed `Forumind*` directories, targets, and identifiers to `WukongMind*`. Per [next-phase.md](next-phase.md), keeping the forum agent untouched alongside the browser agent and adding a separate third model role for the browser agent are superseded ([next-phase.md §6](next-phase.md#6-where-every-existing-piece-goes) and [§7](next-phase.md#7-milestones)); App Store cleanup also runs as its own milestone ([next-phase.md §9](next-phase.md#9-handling-old-code)). The M3 and M4 file-level change lists remain useful references (under `WukongMind/`).

This document maps the existing Forumind codebase (`main`) against the [WukongMind requirements](requirements.md) and defines the concrete file-level change list for milestones `M1` through `M4`. No code, project, or configuration files are modified in `M0`.

### 2.1 Explicit Callout: Non-Discourse / Non-Forum Block Locations to Remove

   - `PageContext.make(url:title:facts:knownForum:registry:)` (`:101-159`) returns `PageContext(url: url, state: .notForum)` at `:150-152` once `matchingFacts != nil` and neither `registry.recognize(facts:url:)` (`:115`) nor `knownForum` (`:135`) matched, or `PageContext(url: url, state: .maybe)` at `:153-155` when `registry.looseTopicID(in: url) != nil`.

## 4. Risks and Open Questions for the Owner

1. **Coexistence of Browser Agent Mode and Forum Modes in `AssistantPanel` (`requirements.md` §2 row 8, §7, §11)**:
   - *Context*: Forumind's `AssistantPanel` (`Forumind/SummaryPanel.swift:27-116`) switches between `Summary`, `Chat`, and `Ask the forum`. In WukongMind, the forum features stay as they are (`requirements.md` §2 row 8, §11), and the new general browser Agent mode lives beside them and works on every site.
   - *Question*: On recognized forum pages, should the new browser Agent mode appear as a fourth tab in `AssistantPanel` beside `Summary · Chat · Ask the forum` (while being the default/only tab on non-forum sites), or should the browser toolbar's Agent button (`requirements.md` §7) open the browser Agent mode directly on all sites?
2. **Rename Source Folders (`Forumind/` -> `WukongMind/`) vs. Keep Target Folder Names**:
   - *Question*: Should we keep the existing `Forumind/`, `ForumindShare/`, `ForumindTests/` directory and Xcode target names (updating only bundle IDs, `CFBundleDisplayName`, App Group, iCloud container, and URL scheme as listed in §3.1) to keep git diffs clean and preserve upstream compatibility, or rename the directories and `.xcodeproj` targets as well?
3. **CSP & Execution World Interaction (`M0` Parallel Task Dependency, `requirements.md` §3)**:
   - *Risk*: Strict site CSP headers (`script-src`, `style-src`, `connect-src`) may block dynamically created `<script>` tags or `.page`-world `eval` on some sites, while `.page`-world access is still needed when `run_js` or a userscript inspects page-defined JS globals.
   - *Mitigation*: Apply the findings from the parallel `M0` CSP and execution-world verification task directly in `M1`'s `AgentBridge` (`run_js` and `inject_css`) and `M2`'s `ScriptStore`.
4. **`WKWebView` Memory Footprint with Multiple Tabs (`M3`)**:
   - *Risk*: Keeping many live `WKWebView` instances in memory simultaneously on iPhone can trigger WebKit content-process termination (`webViewWebContentProcessDidTerminate` at `ForumBrowser.swift:1001`).
   - *Mitigation*: Reuse `ForumBrowserModel.handleWebContentTermination` (`:779-809`) per tab and lazily instantiate or hibernate background tabs' `WKWebView`s when tab count grows.
