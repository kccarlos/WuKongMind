# Flaky Tests & CI Quarantine Status

> **Update (WUKO-59):** CI now retries failed tests (`-retry-tests-on-failure -test-iterations 3`) and lists the ones that needed a retry in the job summary; the retry-free statement below is historical.

`TEST_RUNNER_CI` and `-retry-tests-on-failure -test-iterations 3` have been removed from `.github/workflows/ci.yml`, and no test in the repository is skipped based on the `CI` environment variable. All systemic races and previously flaky tests remain deterministically fixed without weakening assertions — verified on 1.1.4 across 3 consecutive retry-free CI runs ([`43380623190`](https://github.com/kccarlos/WuKongMind/actions/runs/43380623190), [`43382765210`](https://github.com/kccarlos/WuKongMind/actions/runs/43382765210), [`43384568645`](https://github.com/kccarlos/WuKongMind/actions/runs/43384568645); earlier 5-run baseline: [`43314534253`](https://github.com/kccarlos/WuKongMind/actions/runs/43314534253), [`43314538180`](https://github.com/kccarlos/WuKongMind/actions/runs/43314538180), [`43314543200`](https://github.com/kccarlos/WuKongMind/actions/runs/43314543200), [`43314547360`](https://github.com/kccarlos/WuKongMind/actions/runs/43314547360), [`43314553283`](https://github.com/kccarlos/WuKongMind/actions/runs/43314553283)).

## Systemic Races Fixed (`WukongMind/` & Test Harnesses)

1. **`WatchNotifier` `UNUserNotificationCenter` XPC hangs and late publishes (`WukongMind/WatchSupport.swift`)**:
   - `AppModel.init` spawns `refreshNotificationAuthorization()`, and `checkWatchedTopics` posts local notifications when the app is not `.active` (headless CI simulator). Unlike `SpotlightIndexer`, `TopicActivityDonor`, and `WukongMindShortcuts` in `AppModel+System.swift`, `WatchNotifier` did not guard `!AppModel.isRunningTests`, causing 300 s `usernoted` XPC hangs (killing `WukongMind.app` in `StateTransitionTests.testStreamingProgressTicksDoNotPublishAppModelAndClearAtEnd`, run [`43279934768`](https://github.com/kccarlos/WuKongMind/actions/runs/43279934768)) and late `@Published var notificationsAuthorized` mutations during unit tests.
   - **Fix**: Guard `WatchNotifier.isAuthorized()` and `WatchNotifier.requestAuthorization()` with `!AppModel.isRunningTests`.
2. **Unused live `AppModel` and `RootView` in unit-test host (`WukongMind/WukongMindApp.swift`)**:
   - Launching `WukongMind.app` as `TEST_HOST` instantiated a live `AppModel()` loading `state.json`, mounted `ContentView` with a background `WKWebView`, attached `SystemEntry.attach(app)` asynchronously in `.task`, and wired `UNUserNotificationCenter` / remote-notification delegates while 1,000+ unit tests ran in the same process.
   - **Fix**: Keep `BGTaskScheduler` task-identifier registration in `AppDelegate`, skip notification/push registration when `AppModel.isRunningTests` is `true`, and host a lightweight `Color.clear` window scene without instantiating the live `AppModel`.
3. **Unintended live outbound `WKWebView` navigations during `AppModel.init` (`WukongMind/AppModel.swift`)**:
   - `AppModel.init` called `loadHome(silentOnFailure: true)` whenever a seeded snapshot had a pinned or visited forum (`https://forum.example.com`, `https://news.ycombinator.com`, `https://example.com`), triggering 150+ real external WebKit loads and 30 s `fetchForumResource` waits during unit tests.
   - **Fix**: Guard `loadHome(silentOnFailure: true)` in `AppModel.init` with `!Self.isRunningTests`, and call `app.browser.stopLoading()` / `session.invalidateAndCancel()` in test harnesses.
4. **Superseded `WKNavigation` IPC race in `ForumBrowserModel` (`WukongMind/ForumBrowser.swift`)**:
   - `WKNavigationDelegate` callbacks wrapped state updates in unstructured `Task { @MainActor in ... }` blocks without checking whether the `WKNavigation` had been superseded by a newer load. A `didFinish` or `didFail` from an earlier page could execute after a new load started from Home and clear `loadStartedFromForumsHome`, `holdsHomeOverLoad`, or `suppressLoadError`.
   - **Fix**: Track `activeNavigation` across programmatic and in-page navigations and update navigation flags synchronously on `@MainActor`, ignoring stale callbacks from superseded navigations.
5. **Simulator `ScreenTimeCore` cooperative-pool starvation (`WukongMind/ForumBrowser.swift`, `WukongMindTests/ContentBlockerTests.swift`, `WukongMindTests/Sites/SiteRecognitionTests.swift`)**:
   - On iOS Simulator, windowed `WKWebView`s instantiate `STScreenTimeWebBrowserSettingsObserver` (`ScreenTimeCore`), blocking Swift's 3-thread cooperative pool on `ScreenTimeSettingsAgent` / `dasd` XPC.
   - **Fix**: Preload `ScreenTime` / `ScreenTimeCore` frameworks before swizzling `STScreenTimeWebBrowserSettingsObserver.startObserving` so lazy framework loading cannot bypass the swizzle, and apply `ForumBrowserModel.disableWebKitScreenTimeForTesting(in:)` to every direct `WKWebView` helper in `WukongMindTests`.
6. **Premature `jumpToBottom` cancellation and upward-scroll `atBottom` re-arming across nested `LazyVStack` rows (`WukongMind/SummaryPanel.swift`)**:
   - `ChatScrollTracker` cancelled `scrollTask` whenever `new.offsetY < old.offsetY - 1` even without user interaction (`!userScrolling`). When `jumpToBottom` scrolled across 281 lazy summary rows into a tall nested `MarkdownView` `ChatBubble`, an upper row shrinking by >= 2 pt aborted `scrollTask` and set `atBottom = false`, stranding the scroll view ~2,500 pt above the new message. Conversely, when a reader scrolled upward while streaming, offscreen `LazyVStack` height collapses transiently reported `nearBottom == true` despite `new.offsetY < old.offsetY`, re-arming `atBottom = true` and yanking the scroll view back to the bottom on the next token.
   - **Fix**: Cancel `scrollTask` only on real user interaction (`onScrollPhaseChange`), run bounded catch-up passes after `settleScroll` if nested lazy content is still expanding (`!metricsBox.nearBottom`), and re-arm `atBottom = true` from `!atBottom` only when `scrollTask != nil`, scrolling downward (`new.offsetY > old.offsetY`), expanding the viewport, or when content fits within the viewport.

### `ForumPacingTests` background checks (WUKO-54 CI)

`testBackgroundCheckCancelledMidRequestLeavesThatTopicDue` and `testBackgroundChecksStopAtTheBudgetAndResumeWithTheRest` failed once in CI. They did **not** reproduce locally: 10 iterations each (`-test-iterations 10`, iPhone 18 Pro, parallel testing off), 20 of 20 passed on the WUKO-54 branch and 20 of 20 on `origin/main` (`df5db88`). Both tests still use the fake pacing clock and every assertion is unchanged.
